# Стратегия «СинтексПруф» — B2B TechNet-продукт для IT-команд

Документ дополняет презентацию `СинтексПруф_TechNet_v2.pptx` и отвечает на три вопроса:
кому нужна платформа, за сколько её реализовать и как продавать, какими преимуществами
она должна обладать, чтобы опередить конкурентов и реально работать в инженерной среде.

Все цифры — оценки для планирования и CustDev; значения, требующие проверки на пилоте,
помечены «(проверить)».

---

## 1. Кому нужна платформа (ICP)

### 1.1. Первичный сегмент: ИТ-команды с обязательным Code Review

| Параметр | Описание |
|---|---|
| Размер команды | 10–500+ разработчиков, есть PR/MR-процесс и CI/CD |
| Боль | Senior/Lead тратят до 20–30% времени на ревью (тезис питча, замерить на пилоте); обратная связь по PR задерживается; AI-код приносит ошибки и уязвимости |
| JTBD | «Давать обратную связь по pull request за минуты, а не дни, — без потери качества и безопасности» |
| Вертикали | финтех (внутренние стандарты, ИБ), телеком, ритейл/эком с большими dev-подразделениями, ИТ-интеграторы и аутсорс (много проектов, junior-heavy команды), продуктовые компании, госсектор (требования контура, импортозамещение) |

### 1.2. Кто использует, кто покупает, кто продвигает

- **Пользователи:** разработчики (получают комментарии прямо в PR), ревьюеры, тимлиды.
- **Покупатели:** CTO / Head of Engineering (бюджет на devtools), Head of Platform / DevOps-лиды,
  AppSec/CISO (безопасность AI-кода, политики качества).
- **Champion (внутренний продавец):** senior-инженер или tech lead, у которого ревью — узкое место.

### 1.3. Сегменты платящего спроса

1. **ИТ-команды / TechNet — первичный.** Перворазработчики, тимлиды, руководители разработки.
   Ценность: первичный фильтр до ручного ревью, скорость обратной связи, предсказуемое качество.
2. **DevOps / AppSec / платформенные команды — первичный.** Политики качества и безопасности,
   quality gates в CI/CD, автоматизация проверок, единый стандарт для всех репозиториев.
3. **HR / обучающие программы — вторичный.** Разбор тестовых заданий кандидатов — удобный
   дополнительный сценарий, но не ядро продаж.
4. **EduNet — частично.** Учебные заведения — только как дополнительный пилот/канал
   **после** успешного TechNet-пилота (проверка учебных работ — та же технология, другой рынок).

### 1.4. Анти-ICP (кому НЕ продавать в первую очередь)

- Команды без PR-процесса и CI (нет места для интеграции — продукт не покажет ценность).
- Одиночные разработчики и хобби-проекты (низкий LTV).
- Учебные курсы до подтверждения B2B-ценности (сначала деньги и кейсы TechNet).

### 1.5. Как проверить ICP за 3–4 недели (CustDev)

- 10–15 интервью: тимлиды/CTO/Head of Platform. Вопросы: сколько времени уходит на ревью,
  как измеряют, что будет с adoption при FP > 20%, кто платит за devtools, как проходит закупка.
- Цель: 3 письма заинтересованности на пилот, подтверждение диапазона цены
  (ориентир — «за разработчика в месяц»), согласование метрик успеха пилота.

## 2. За сколько реализовать и как продавать

### 2.1. Смета разработки (оценка, рынок РФ, команда 4–5 человек)

| Этап | Срок | Команда | Бюджет (оценка) | Результат |
|---|---|---|---|---|
| MVP | 1–2 мес | 2 backend, 1 ML/NLP, frontend part-time, PM part-time (~3–4 FTE) | 2,5–4 млн ₽ | Инкрементальный анализ PR/diff, топ-правила C/C++/Python, отчёт по строкам (CRITICAL/MAJOR/INFO), комментарии в PR/MR (GitHub/GitLab), SARIF, LLM-объяснения с кэшем |
| Валидация | 3-й мес | + QA/методика испытаний | 1–1,5 млн ₽ | Замер FP/FN на эталонном наборе, UX, нагрузочный тест, hardening интеграций |
| Пилот | 4–5 мес | + DevOps part-time, поддержка пилота | 1,5–2,5 млн ₽ | Пилот в IT-команде на реальном репозитории/CI, метрики «до/после», отчёт, кейс |
| **Итого до конца пилота** | **5 мес** | **~20–25 person-months** | **~5–8 млн ₽** | Готовый к продажам продукт с доказанным эффектом |
| Поддержка и развитие | далее | 2–3 FTE part-time | 300–500 тыс ₽/мес | Релизы, расширение правил, on-prem |

**Инфраструктура.** LLM API / GPU — 50–150 тыс ₽/мес на разработке; в проде COGS 5–15%
выручки: тяжёлую работу делает собственный детерминированный анализатор, LLM вызывается
только для объяснений по топ-находкам, ответы кэшируются по хешу диффа.

**Куда уходят деньги по приоритету:** (1) точность и FP — главный риск переделок,
(2) интеграции PR/CI, (3) UX ревьюера, (4) on-prem-контур.

### 2.2. Цена и модель монетизации (гипотезы для проверки в CustDev/пилоте)

| План | Цена (гипотеза) | Для кого |
|---|---|---|
| Team / Pro (SaaS) | 1 500–3 000 ₽ / разработчика / мес (per-seat); альтернатива — per repo 5–15 тыс ₽/мес, per CI-pipeline | Команды 10–100 dev |
| Enterprise / on-prem | 1–3 млн ₽ / год: контур (код не уходит наружу), SSO, SLA, приоритетная поддержка | Финтех, госсектор, крупный бизнес |
| Пилот | 4–8 недель: бесплатно или 100–300 тыс ₽ «с гарантией эффекта» (зачёт в подписку при успехе) | Первый внедренческий цикл |
| B2Edu / HR | По остаточному принципу, как дополнительный канал | EduNet, рекрутинг — после TechNet |

**Ориентиры рынка.** Зарубежные аналоги: CodeRabbit ≈ $19/dev/мес, Snyk ≈ $25/dev/мес.
Российская цена с дисконтом 30–50% при локальном контуре — конкурентноспособна.

**Unit economics.** Маржа 70–85% (кэш LLM-ответов + собственный анализатор);
LTV команды 20 dev при 2 500 ₽/мес ≈ 600 тыс ₽/год; окупаемость продажи — при CAC < 150–200 тыс ₽.

**Формула ROI для покупателя (главный аргумент продаж):**
`Экономия = часы senior × ставка (3–5 тыс ₽/ч) × 20–30% времени ревью`.
Для команды 20 dev экономия ≈ 2–4 млн ₽/год при стоимости подписки ~0,5–1 млн ₽/год.

### 2.3. Как продавать (GTM)

**Двойное движение:**
- *Bottom-up (PLG):* бесплатный tier / OSS-friendly, бот комментирует PR → тимлид видит
  экономию → платная командная подписка. Самая короткая сделка (2–6 недель).
- *Top-down:* пилот в одной команде → rollout на подразделение → enterprise/on-prem-контракт
  (цикл 3–9 мес; закупка, ИБ, compliance).

**Сценарий сделки:**
1. Shadow-mode пилот 4–8 недель на реальном репозитории (бот не блокирует, только советует).
2. Замер «до/после» по согласованным метрикам (см. §3.3).
3. Коммерческий rollout: подписка или on-prem-договор.

**Каналы:** партнёры-интеграторы (внедрение), TechNet-экосистема и ДГУ (пилотные площадки),
отраслевые конференции и Habr (кейсы пилотов), прямые продажи через champion-контакты.

**Что ускоряет сделку:** on-prem-режим, гарантия по FP, готовый ROI-калькулятор,
чек-лист требований ИБ, российская локация и поддержка.

## 3. Преимущества: как опередить конкурентов и быть полезными в работе

### 3.1. Полезность в рабочей среде — без этого продукт не выживет

Порядок важности (по данным индустрии devtools и логике adoption):

1. **PR-native UX.** Комментарии к конкретным строкам прямо в PR/MR — ревьюер не уходит
   в отдельный портал. Отчёт по строкам, severity, объяснение, предложение патча.
2. **Низкий уровень ложных срабатываний (FP) — главный убийца adoption.** Advisory-режим
   на старте, калибровка правил под команду, показ «только блокирующих» находок.
   Цель: precision ≥ 80–90% на блокирующих правилах (проверить на пилоте).
3. **Скорость.** < 3–5 минут на pull request, инкрементальный анализ только diff —
   иначе бот не встроится в CI.
4. **Приоритизация.** Скоринг находок (0–100, severity): ревьюер смотрит 10 важных,
   а не 100 шумных. Дайджест для тимлида — качество команды за неделю.
5. **Объяснимость + фикс.** «Почему это плохо» + «как исправить» (autofix suggestion) —
   это то, что экономит время senior-инженера.
6. **Не мешает работать.** Shadow mode 2–4 недели → сравнение с ручным ревью →
   включение quality gates. «Не блокирует, пока не доказал».
7. **Доказательность.** Встроенный дашборд метрик «до/после»: время ручного ревью,
   FP/FN, time-to-merge, defect leakage, доля PR с принятыми бот-комментариями (adoption).

### 3.2. Конкурентные преимущества — что отрезать у каждого

| Соперник | Его сила | Наш ответ |
|---|---|---|
| SonarQube (SonarSource) | Зрелые правила качества и безопасности, self-hosted | PR-native ИИ-ревью с объяснениями и фиксами, лёгкое внедрение, импортозамещение; компенсируем «глубину правил» фокусом на топ-100 правил C/C++/Python + ИИ-слой |
| CodeRabbit / Copilot Review | Удобное ИИ-ревью PR, быстрый старт | Глубокий детерминированный статический анализ + on-prem (код не уходит в облако) + российская локация + provenance «человек / LLM» |
| Внутренние скрипты и линтеры | Бесплатно, «уже есть» | Единая политика качества для всех репо, скорость внедрения (дни), ИИ-объяснения, метрики вместо ощущений |

**Уникальность, которой нет ни у кого в связке:** комбинация
«детерминированные правила + ИИ-объяснения + on-prem-контур + определение происхождения кода
(человек / LLM)». Последняя функция — вторичный сценарий для HR/EduNet, но и для enterprise-
compliance («какой код приходит от ассистентов»).

### 3.3. Метрики победы на пилоте (success criteria)

| Метрика | Цель пилота |
|---|---|
| Время ручного ревью | −25–30% |
| False positive rate (блокирующие правила) | ≤ 15–20% |
| Time-to-merge | −20% |
| Adoption в PR | ≥ 50% PR с бот-комментариями, не отключёнными командой |
| Defect leakage | −10–20% дефектов, всплывающих после ревью |

### 3.4. Моты (защита от копирования)

1. Калиброванный под российские codebase набор правил C/C++/Python и эталоны FP/FN.
2. Связка «правила + ИИ + provenance» в одном приватном контуре.
3. Датасет реальных PR пилотных команд для дообучения и валидации.
4. Партнёрские пайплайны (TechNet, интеграторы) — каналы сбыта, которые трудно воспроизвести.

### 3.5. Риски и как их снимать

| Риск | Снятие |
|---|---|
| Шум и FP → команда отключает бота | Shadow mode, калибровка, показ только топ-находок |
| LLM-объяснения «галлюцинируют» | Правила первичны (детерминированная проверка), ИИ только объясняет; каждая находка привязана к правилу и строке |
| Медленные enterprise-продажи | Team-tier self-serve как вход, on-prem — как апсейл |
| Облачные конкуренты дешевле | Приватность контура, on-prem, российская поддержка, ROI-аргумент |
| Экономия «не видна» | Метрики до/после встроены в продукт — отчёт пилота готовится автоматически |

## Приложение. Быстрый ROI-калькулятор для продаж

Вход: `N` разработчиков, `H` часов ревью в неделю на senior-ревьюера, доля senior `S`,
ставка `R` ₽/час (3–5 тыс), эффект `E` = 25% (цель пилота).

`Годовая экономия ≈ N × 20% × 40 ч/мес × 12 × R × E` — для N=20, R=4 000 ≈ **1,9 млн ₽/год**
(консервативно; при полной загрузке senior-ревью — 2–4 млн ₽/год).

Стоимость подписки при 2 500 ₽/мес × 20 = **600 тыс ₽/год** → ROI ≈ **3× уже на первом году**,
без учёта сокращения defect leakage и ускорения time-to-merge.
